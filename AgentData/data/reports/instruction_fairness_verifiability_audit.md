# Instruction 公平性与可验证性审查报告

> 核心问题：招聘方提供的 Instruction，是否足以让 Agent 理解任务、正确完成任务，并让考官公平、客观地判断完成质量？
> 本报告面向人工阅读，通俗易懂；详细技术版分析另存于 `data/instruction_audit_detailed.md`。

## 第一部分：Instruction 要求了什么？

Instruction 是一段英文任务说明，用中文概括如下：

- **任务目标**：连锁餐饮品牌"桥岸小馆"要开经营复盘会，需要说明两个相邻年度区间（2023→2024、2024→2025）全品牌门店客流的变化，并区分"老店自身的变化"和"开店、关店带来的组合变化"，还要分解到早餐、午餐、晚餐三个餐段。
- **输出内容**：每个期间先给品牌总量结论，再给门店组合桥和餐段贡献；原始值、绝对变化、分母、带符号贡献、门店状态、期间、单位、勾稽（闭合）关系都必须能重算、能追溯回台账。
- **执行顺序**：先创建空的交付工作簿，用中文渐进填写；填任何数值之前，先阅读环境中已有的经营操作规范。
- **交付要求**：只交付一个可编辑的 XLSX 文件。
- **结构宽容**：工作表名称、列名、表顺序、宽表/长表都可以不同；但两个比较期间、持续/新开/关闭三类影响、三个餐段、所有状态边界、抵消效应和"正式采用结论"一样都不能少。
- **执行限制**：源文件只读、禁止联网。
- **附带提示**：可以直接运行一个 solve.py 脚本生成完整答案工作簿。

## 第二部分：任务要求是否清楚？

逐项检查关键业务定义（"定义来源"区分：Instruction 明说 / 其他材料明说 / 可合理推导 / 无法确定）：

| 检查对象 | 定义是否明确 | 定义来源 | 存在的问题 |
|---|---|---|---|
| 品牌总客流 | 明确（可推导） | Instruction 给出口径方向，单位与范围由台账「口径说明」B4 补全 | 公式未直写，但"全部门店求和"是唯一合理解释 |
| 品牌净变化 | 明确（可推导） | Instruction 的方向描述 + Gold 的"净增"表述 | 无实质歧义 |
| 持续经营/新开/关闭 | 部分明确 | **只在台账「口径说明」B5（中文）**，Instruction 用了英文术语但未重申 | 新开门店基期、关闭门店本期填的 0 是"不在经营范围"的占位，**不是真实零客流**——这一点 Instruction 完全没提醒 |
| 绝对影响 | 部分明确 | **只在公开评分规则 Rubric 中写明公式**（持续=本期−基期；新开=本期；关闭=−基期），Instruction 未给 | 只读 Instruction 的 Agent 不知道关闭门店必须体现负向影响 |
| 净变化分母 | 明确 | Instruction 原文明确要求以品牌净变化为分母 | 无歧义 |
| 带符号贡献 | 部分明确 | 可由"带符号贡献÷分母"推导，Gold 有完整数值 | 未提示结果会超出 0%–100%（新开贡献 +185.42%），Agent 若习惯性截断或归一化会破坏闭合关系 |
| 餐段贡献 | 部分明确 | 台账餐段齐全，公式可由材料推导，Rubric 补全了三分量要求 | 餐段贡献与门店组合贡献是两个维度，Instruction 未点明 |
| 抵消效应 | 部分明确 | 术语未定义，靠带符号贡献体系自然支撑 | 正向（开店、增长）与负向（关店、下滑）如何相抵得到净变化，需自行理解 |
| 正式采用结论 | 不明确 | **四处皆无定义**，Gold 里有个"采用"标记但也只是展示 | 什么叫"正式采用"、依据什么确定，没有任何说明——Agent 无法明确判断自己需要输出什么，考官也缺少客观判定标准，属于重要的可验证性风险（详见下方补充） |
| 数据追溯/可重算 | 部分明确 | Instruction 提出要求，Gold 用"来源表+来源单元格"实现 | 追溯要到什么粒度（表？行？单元格？）没有规定 |

**小结**：核心业务口径在数值上都能收敛到唯一正确解释，但"状态判定、占位零语义、三类影响公式"这三块关键知识**不在 Instruction 里**，而在中文材料或评分规则里。英文 Instruction + 中文材料的组合，对 Agent 的材料阅读提出了隐含要求。

**补充：关键业务概念辨析**

- **零值、缺失值、无记录、不适用是四个不同概念**。本材料中：新开门店基期、关闭门店本期的 0 是"不在经营范围"的占位值（由口径说明 B5 的"不在经营范围"可推知），不是观测到的真实零客流；表内不存在缺失单元格；新开/关闭门店的同比"不适用、表内留空"（口径说明 B6）。把占位 0 当真实客流、把"留空"当 0、把"不适用"当"无增长"，是三个不同的错误。
- **带符号贡献**：保留正负号（关闭门店为负）；允许超过 100%（新开贡献 = 本期全部客流 ÷ 净变化，期间一达 +185.42%）；分母为零时期望贡献不可定义（本材料分母为 +48/+59，未发生；规则未给出零分母处理方式）；闭合条件为同一期间内三类贡献之和 = 100%、三餐段贡献之和 = 100%（Gold 控制表有对应断言）。
- **门店组合桥与餐段归因是两个不同维度**：组合桥按门店状态（持续/新开/关闭）分解净变化；餐段归因按早餐/午餐/晚餐分解同一个净变化。两者各自闭合，且交叉成立——每个餐段内部还按三类门店状态再拆三分量（持续增量、新开流入、关闭流出），该拆分要求见评分规则 R5 与 Gold 餐段归因表，Instruction 只说了"餐段贡献"未点明要拆三类门店。数值全对必须同时满足两个维度，只做一个维度的闭合不构成完整归因。
- **"正式采用结论"的深层问题**：Instruction 把它列为"不得省略"的要素，但从未解释其含义——是指最终交付中明确陈述的品牌级结论？还是需要某种确认程序？环境中不存在任何确认机制。由此产生双重风险：Agent 侧无法明确判断要输出什么（可能只给数据不给结论，或给出与数据不一致的口头结论）；考官侧也缺少客观判定标准（无法区分"正式采用"与"仅供参考"的结论）。这是一个重要的可验证性风险。

## 第三部分：原始材料是否足够？

**足够。** 阶段二已从原始台账独立算出全部结果：

- 数据完整：2 个比较期间、6 家门店、3 个餐段，共 36 条明细，无缺失、无重复。证据：台账「客流对比_2024」「客流对比_2025」各 18 条明细 + 合计行。
- 状态可识别：每家店每期都有明确的经营状态列。证据：台账口径说明 B5 给出了三分类规则，数据行 D 列逐一标注。
- 餐段数据齐全：每店每期早/午/晚三行。
- 口径有说明：单位（千人次）、状态口径、同比口径集中在「口径说明」表。证据：口径说明 B4:B6。
- 独立计算已完成：品牌总量 374→422（+48）、422→481（+59）；组合桥 23+89−64=48、31+79−51=59；餐段 −11+21+38=48、1+17+41=59，全部闭合。证据：Independent Baseline（`data/fact_baseline.json`、`data/audit.db`）。

**Gold 核验统计**：414 项待校验数据，其中 412 项由代码自动校验通过，2 项措辞类项目经人工复核通过，最终 414 项全部通过。
**414 项全部通过证明了什么**：Gold 六张表里的每个业务数字、门店归属、来源指向都是正确的，可以当作有效参照。
**它不能证明什么**：不能证明 Instruction 写得清楚（Gold 是出题人事后整理的标准答案，不是 Agent 看到的任务说明），也不能证明评分公平。

## 第四部分：结果是否能够验证？

| 验证对象 | 验证方式 |
|---|---|
| 品牌总量、净变化、增幅 | 代码可从 36 条明细独立复算（阶段二已完成） |
| 三类门店的绝对影响 | 代码可复算；关闭门店符号可程序检查 |
| 带符号贡献及贡献合计=1 | 代码可复算 |
| 12 个"期间×门店"的状态 | 代码可从经营记录独立判定 |
| 三餐段贡献及两层闭合 | 代码可复算 |
| 76 个原始值的逐格来源追溯 | 代码已与台账逐格比对（全部一致） |
| 中文结论文义（最大推动因素、净抵消） | 需要人工/AI 语义判断，但有明确计算依据（增量最大者、负增量餐段） |
| "正式采用"表述是否合规 | **重要的可验证性风险**：定义本身缺失，Agent 不知该输出什么，考官也缺少客观判定标准，只能靠人工自由心证 |
| 源文件只读、禁网是否遵守 | 当前材料无法验证 |
| solve.py 是否存在、各 Agent 环境是否一致 | 当前材料无法验证 |

可重算性有明确验收标准（数值精确一致、比率在容差内、单位换算一致、来源可定位到单元格），且已实际执行通过。

**"可重算"到底指什么**：这里要区分两件事。一是**考官独立复算**——拿到答案后，用原始台账手工或写代码重新计算，核对数值是否一致；这是本次审查实际执行的方式，所有数值链都已通过。二是 **Excel 自动动态重算**——工作簿内的公式在改输入后自动更新结果。Instruction 原文 "recalculable" 并未指明是哪一种；公开评分规则给出了统一标准："公式或静态值均可，差异不构成错误"，即只要数值正确、来源可追溯，静态值同样合格，不强制动态公式。本报告不擅自认定静态值必然合格或必然不合格——按公开规则，静态值与公式是等价表达，但评分实现是否兑现这一承诺见第五部分（这是评分公平性问题）。

## 第五部分：任务是否公平？

先分清两个层面：**任务公平性**关注"Agent 是否获得相同的条件和明确的要求"；**评分公平性**关注"相同质量的结果是否得到相同的分数"。Instruction 的问题和评分器的问题要分开评判。

**任务公平性（Instruction 层面）——基本良好，一处待确认**

Instruction 文本本身的公平性设计是好的：明确允许工作表名、列名、表顺序、宽窄表不同，明确允许公式或静态值，篇幅格式不产生分数。所有 Agent 拿到的原始材料相同。需要扣分的是一项**待确认事项**：solve.py 和"经营操作规范"在材料中都不存在，目前无法确认每个 Agent 面对的是否是相同环境。证据：Instruction 的提示与运行要求 vs 考试包实际文件清单。若经确认各 Agent 环境一致，则任务公平性通过。

**评分公平性（评分器层面）——存在两处违背公开承诺**

公开规则（Rubric）写得公平，但评分器（Scorer）的实现与承诺存在矛盾：

1. **暗中奖励公式**。公开规则说"公式或静态值均可"，但评分器内部有一个未公开的检查项：答案里含公式且与"总量/分母/贡献"等词同行出现就额外加分，纯静态值的正确答案会被封顶打折。后果：数值全对的静态答案比同样全对但含公式的答案低约 2–6 分。证据：公开规则 `rubric/current_rubric.md` 等价性条款 vs 评分器 `scorer/fresh_owner_policy.py` 中的公式依赖逻辑。
2. **追溯检查认关键词**。追溯是否合格靠"来源/源/追溯"等固定词判断，写成"出处""依据"的等价正确答案可能失分。证据：同上文件中的追溯扫描逻辑。

此外两项属于评分机制透明度问题，同样影响"相同质量结果是否得到相同分数"：**有超出 Instruction 的评分要求**（例如评分规则要求检查"同比边界"和"持续经营分析不等于品牌总量"，但 Instruction 从未向 Agent 提出这些要求——做了不加分、没做可能扣分）；**公开权重与实际打分的权重不一致**（公开的七项权重表与实际结算用的内部权重、折扣系数不同，还区分"历史工件直接回放旧分"和"新工件重新打分"两条路径，不同答案之间的分数可比性变差）。证据：`scorer/scoring_params.json` 与 `scorer/fresh_owner_policy.py` 的权重表对照；`scorer/validator.py` 的历史工件回放逻辑。

**特别声明：以上评分公平性问题全部属于评分器缺陷，不应归咎于 Instruction。** Instruction 的公开承诺本身（结构宽容、公式与静态值等价）是明确且公平的，是评分实现没有兑现承诺。

## 第六部分：发现的问题及最小修复方案

**问题 1：Instruction 引用的"经营操作规范"没有以它暗示的形式存在，业务规则分散在中文台账中。**
为什么有问题：Instruction 让 Agent"先查阅环境中的经营操作规范"，环境中并没有独立的规范文件。但要说明：**这不等于没有业务规范**——台账的「口径说明」表已经覆盖了必要规则：单位（千人次，B4）、门店状态三分类口径（B5）、同比适用范围与留空规则（B6），配合数据行本身的状态标注，状态判定、同比边界、餐段结构这些规则是明确的。真正的问题有两个：一是这些规则以中文存在于源数据里，Instruction（英文）没有引导 Agent 去那里找；二是仍有少数规则在任何材料中都找不到（见下）。
实际影响：规则主体可得，风险主要是发现成本与语言映射负担，而非规则整体缺失。
已明确 vs 仍缺失：已明确 = 单位、状态判定、同比留空、餐段结构（口径说明 B4:B6 + 数据行状态列）；仍缺失 = 三类门店绝对影响的计算公式、贡献率取值范围提示、"正式采用结论"的定义（后两者仅间接见于评分规则或 Gold）。
证据：Instruction 第二段；台账「口径说明」B4:B6；考试包文件清单（无独立规范文件）。
最小修复：Instruction 明确说明"经营操作规范即台账中的口径说明表"，或直接内嵌状态口径与影响公式。

**问题 2：solve.py 的存在性与可访问性无法确认。**
为什么有问题：Instruction 附带的运行提示暗示脚本就在环境里，但材料中没有，真实运行环境又不可见。
实际影响：若脚本不存在，提示是误导；若各 Agent 环境不一致，评测的"相同条件"前提不成立（这是最坏情况，需向评测方确认）。
证据：Instruction【交付提示】；考试包内无 solve.py。
最小修复：向评测方确认；确认不了就从 Instruction 删除该提示。

**问题 3：评分器暗中奖励公式，违背公开承诺。**
为什么有问题：公开规则白纸黑字"公式或静态值均可"，实际打分却对公式加分、对静态值封顶。
实际影响：直接造成评分不公平——同样全对的答案因表达方式不同而分数不同（假阴性/假阳性来源）。
证据：`rubric/current_rubric.md` 等价性条款 vs `scorer/fresh_owner_policy.py` 公式依赖逻辑。
最小修复：删除该检查项，或让它对静态值完全中性。

**问题 4：实际打分权重与公开权重不一致。**
为什么有问题：考生和审计者看到的是一套权重，机器实际用的是另一套，还有折扣系数和两条结算路径。
实际影响：分数无法按公开规则复算，可比性差，审计困难。
证据：`scorer/scoring_params.json` vs `scorer/fresh_owner_policy.py`；`scorer/validator.py` 的历史工件回放逻辑。
最小修复：公开真实权重表，或让两套权重一致。

**问题 5：关键公式与占位零语义没有写进 Instruction。**
为什么有问题："关闭门店=−基期客流""新开门店基期的 0 是不在经营范围"只存在于评分规则和中文材料里。
实际影响：只认真读 Instruction 的 Agent 处于信息劣势，可能把占位零当真实客流，连锁错状态与同比。
证据：Instruction 全文 vs `rubric/current_rubric.md` 门店组合桥条款；台账「口径说明」B5、客流对比_2024!F16:F18（新开湖滨基期为 0）。
最小修复：在 Instruction 中补三句话：状态判定口径、占位零语义、三类影响的计算公式。

## 第七部分：最终结论

| 评价维度 | 结论 |
|---|---|
| 任务目标是否明确 | 通过（做什么、交什么、哪些不能少，都写清了） |
| 业务定义是否准确 | 部分通过（核心口径数值无歧义，但状态口径、影响公式、正式采用定义缺失，靠材料与评分规则补全） |
| 原始材料是否充分 | 通过（数据完整、口径可查、已独立复算全部结果） |
| 结果是否可验证 | 部分通过（数值链全部可程序化复算与追溯；"正式采用"因定义缺失构成可验证性风险） |
| 任务是否公平 | 部分通过（Instruction 承诺公平且条件相同性待确认；评分公平性见下一行，属评分器问题） |
| 评分机制是否公平 | 不通过（评分器两处违背公开承诺：暗中奖励公式、权重不一致，需先修复） |
