# AGENT 开发行为规范

本文件约束 Kimi Code 等 AI 编程工具在本项目中的开发行为。开始任何开发前必须先阅读 `README.md` 与本文件。

## 一、目录边界

1. 项目根目录固定为 `WUWEITEST/AgentData/`，一切工作以该目录为基准。
2. 所有新增文件（代码、数据、数据库、报告、测试、配置）必须位于 `AgentData/` 内。
3. 不得创建或修改 `AgentData/` 之外的任何文件（包括仓库根目录及 Back-end、Crawler、Front-end、Python 等目录）。
4. `restaurant-portfolio-traffic-change-audit/` 是招聘方原始考试材料，视为只读：不得删除、覆盖、移动或重命名其中任何文件。
5. 本项目生成的文件与原始考试材料分开存放（生成物放 `data/`、`src/`、`tests/` 等规划目录，不混入考试包）。

## 二、阶段与流程

6. 先阅读 `README.md` 和 `docs/DEVELOPMENT_PLAN.md`，再开始开发。
7. 严格按照 `docs/DEVELOPMENT_PLAN.md` 的阶段顺序实施，一次只做一个阶段。
8. 每个阶段完成后汇报完成内容、文件变更、测试情况、未解决问题，并对照阶段验收条件自检。
9. 每阶段必须等待人工明确批准后才能进入下一阶段；未经批准不得提前实施后续阶段。
10. 阶段推进过程中如发现原计划遗漏，先汇报，经批准后再调整计划。

## 二之二、阶段二节点质量门禁（顺序执行、自动流转、失败中断）

阶段二内部不按人工逐节点批准，而是按节点自动推进，规则如下：

11. 阶段二的六个节点（2.1 材料盘点与口径 → 2.2 数据模型 → 2.3 解析与 JSON 标准化 → 2.4 SQLite 存储 → 2.5 事实基线 → 2.6 质量校验与阶段验收）严格按既定顺序执行，不得调整或跳过。
12. 每节点完成后，立即对照 `docs/DEVELOPMENT_PLAN.md` 中该节点的验收标准逐项验证（运行自动化测试、记录实际结果与证据）。
13. **验收通过**：自动开始下一节点，不等待人工回复。通过的前提是所有必要验收条件满足、无影响下一节点的阻断问题、关键数据可追溯。
14. **验收不通过**：立即停止整个阶段二的后续执行，按失败汇报格式汇报（当前节点、未通过的验收条件、问题证据、问题影响、建议最小修复方案），明确说明已中断、不会继续执行后续节点，等待用户处理或批准修复方案。
15. 不得跳过失败节点，不得带着未解决的阻断问题进入下一节点；修复后重新执行当前节点的验收，通过后才能继续。
16. 不得将需要人工确认的问题擅自判定为通过。
17. 六个节点全部通过后，生成阶段二总结报告（节点完成情况、文件变更、数据规模、SQLite 情况、基线结果、Gold 差异、质量检查、测试结果、非阻断问题、验收建议），然后停止，等待人工验收并明确批准后才能进入阶段三。
18. 阶段三至阶段六继续采用人工阶段门禁；若要在其内部划分节点，须在实施该阶段前向用户明确执行机制，不得擅自改变整体流程。

## 三、数据与证据纪律

11. 优先使用确定性代码（Python/Pandas/OpenPyXL）完成数据解析、计算与核验；AI 负责辅助分析和语义判断，不得代替关键事实核验。
12. 不得编造数据、测试结果、审计证据或开发进度；未完成的实现不得声称完成，不确定的结论须标注为假设。
13. Gold 不是不可质疑的唯一事实源：关键数值必须能从源台账独立复算，并保留计算过程。
14. 所有关键计算必须可追溯、可复核：保留来源文件、工作表、行列、单元格或公式级别的证据定位。
15. 最终答卷中的重要结论必须能够回溯到具体证据，不得只有结论没有依据。

## 四、测试与诚实原则

16. 核心功能必须有自动化测试（Pytest），测试不通过不得标记任务完成。
17. 不得为了通过测试而修改原始数据、篡改期望值或删除失败测试；测试失败应报告根因。
18. 运行测试或构建后检查有无多余产物文件，及时清理。

## 五、设计约束

19. 避免过度设计和无意义的抽象：以笔试题要求的最小可验证实现为准。
20. 不引入不必要的 Web 框架，不开发前端，不添加考试题未要求的依赖。

## 六、汇报要求

21. 每个阶段结束时按固定格式汇报：完成情况、文件变更、测试情况、未解决问题、验收条件自检、是否建议进入下一阶段。
