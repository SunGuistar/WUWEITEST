## 2. 实际结算机制（fresh_owner_policy.py）

`reward = Σ W_k·credit(c_k)`，k ∈ {R4, R5, R6B, R6E, R9}；
`credit = 1.0 if c==1 else α·c`（α = 0.8/0.8/0.8/0.8/**0.7**）。
- **部分分折扣**：任何未达满分的结算项被打 8 折（R9 打 7 折）后才计入——部分完成被系统性压分。
- **未公开的权重、未公开的折扣、未公开的 R9**——三者均不在 current_rubric.md 中。

## 3. R9 公式依赖专项审查（4.4.4）

源码机制（fresh_owner_policy.py:6-21 `r9_dependency`）：
1. 同时打开公式版与取值版工作簿；
2. 对每个期间（2023/2024、2024/2025）× 三组词对（'总','分母' / '组合','贡献' / '餐段','贡献'）共 6 个检查点；
3. 检查点得分条件：某 Sheet 前 5 行文本含该期间年份 → 该 Sheet 存在**某一行**（i）行文本含词对中**任一词**（`any(t in text)`）且（ii）同行存在以 `=` 开头的字符串单元格；
4. 6 点平均为 R9。

性质判定：**R9 检查的是工作簿表面的公式特征，不是业务计算能力。**
- 不读公式内容、不验证公式正确性、不比对数值——只要"公式 + 关键词 + 期间字样"同行共现即得分；
- 与业务正确性零相关：五份 Rollout 数值全对，R9 也全 1（五份各含 536–1412 个公式）；
- **惩罚静态值**：公开规则声明"formulas versus static values are not errors"（current_rubric.md:17），
  静态值全对答案 R9 必然为 0，平白损失 5.99% 权重且无法通过任何业务手段补回——**与公开规则直接矛盾**；
- 误判双向性：无意义公式（如 `=1+1` 与"贡献"同标题行）可得分；正确但静态的答案不得分。
- probe-03 的常数 2 不会骗过 R9（非 `=` 开头字符串，实测其行文本无公式 → R9=0）——该启发式对常数伪装有免疫力，但对"公式形式主义"无免疫力。

这是大规模、可复现的**假阴性**证据链。

## 6. 公平性与稳定性问题清单（按严重程度）

**S1【严重】实际结算体系与公开 Rubric 不是同一套规则。**
影响：考生与审计者按公开规则（R1–R7 权重）无法复算任何分数；R1/R2/R3/R7 做得再好也不加分。
影响对象：全部 5 份 rollout（复算证实）、全部未来工件。证据：fresh_owner_policy.py:3、scorer_behavior.md、scoring_params.json、frozen 复算。已验证：是（5/5 复算吻合）。

**S2【严重】未公开维度 R9 与公开规则矛盾，奖励公式形式主义。**
影响：静态值正确答案系统性损失 5.99%，含公式即得满分该项——与"公式或静态值均可"直接冲突。
影响对象：任何静态值工件（假阴性）；任何含公式工件（无差别加分）。证据：fresh_owner_policy.py:6-21、current_rubric.md:17、scorer_behavior.md。已验证：R9 机制源码确认；五份 rollout R9 全 1（公式数佐证）。

**S3【高】65% 权重（R6B+R6E）由控制表绑定成败决定，非业务数值。**
影响：数值全对的五份 rollout 因此项 0/1 分化产生 0.65 的分差——布局敏感、质量不敏感的大规模假阴性。
影响对象：rollout-01/02/04（实锤）；未来一切布局不合契约的工件。证据：frozen completion 分化 + 阶段三数值核验 + program_judge 绑定逻辑（contract 键缺失，具体键不可核验）。已验证：分数侧 100%；绑定原因侧存在证据缺口。

**S4【高】五份当前分数为 frozen 历史回放，评分不可复现。**
影响：重新评分同样文件会直接返回旧分；同内容不同文件的工件走不同路径，跨工件不可比；历史语义判定版本不可审计。
证据：validator.py:22-30 + 哈希命中核对。已验证：是。

**S5【中】部分分折扣（α=0.8/0.7）未公开且压低部分完成得分。**
影响：probe-02 式"一半全对"的合理比例分被再打 8 折。证据：fresh_owner_policy.py:4。已验证：复算吻合（如 r04 R2=0.9474 不计权重故不可见，但机制存在于全部加权项）。

**S6【中】绑定失败叶子记 0 且无法区分"没写"与"写了但布局不合契约"。**
影响：rubric 承诺"绑定失败不整体归零"，但 0 叶子在权重体系中被放大；无诊断输出。证据：program_judge.py:70-148 + rubric R2 条款 + frozen 记录。已验证：结果侧确认，原因侧缺口同 S3。

**S7【中】R8 追溯关键词启发式未公开（当前权重 0）。**
影响：若未来赋权，"出处/依据"等同义表述将失分；当前不影响总分。证据：fresh_owner_policy.py:22-32、scorer_behavior.md。已验证：源码确认；权重 0 由 fresh 权重表确认。

**S8【低】evaluator_instruction_adoption 直接判 0（validator.py:68）。**
合理门槛，但未在 rubric 展开说明；低影响。

## 8. 核心问题的回答

**当前 Scorer 是否真正按照公开 Rubric，公平地评价 Agent 的实际业务质量？**

**不是。** 三重偏离，均有硬证据：
1. **规则偏离**：实际结算的权重结构（R4/R5/R6B/R6E/R9 = 23.45/5.56/30/35/5.99%）与公开 Rubric（R1–R7）不是同一套，40% 声明权重归零、存在未公开维度（S1/S2）；
2. **质量不敏感**：决定 65% 分值的 R6B/R6E 由契约表绑定（布局）而非数值正确性决定；数值全对的五份 rollout 因此产生 0.65 的分差（S3/S4，结合阶段三审计构成系统性假阴性）；
3. **形式敏感**：R9 奖励"公式+关键词"的表面特征，惩罚公开规则承诺等价的静态值表达（S2）。

公平性修复的最低要求（供阶段五参考，本阶段不重构）：公开真实权重表、删除或中性化 R9、让数值正确性而非布局绑定决定闭合类维度、冻结分与重算分并行披露。
