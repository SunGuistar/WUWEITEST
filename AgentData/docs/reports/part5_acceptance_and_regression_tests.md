# 第五部分：验收结论与回归测试

## 5.1 最终验收结论

| 项目 | 结论 |
|---|---|
| 任务状态 | **需要返修** |
| 评分器状态 | **不可用** |
| 主要阻断问题 | ①公开评分规则与实际评分是两套体系（实际只结算五个内部项，四个公开维度权重归零，含一个未公开的"公式检查"）；②65% 的分值由"评分器能否识别表格布局"而非业务数值决定——数值全对的五份 rollout 得分横跨 0.29–1.00，已证实三例假阴性；③隐藏公式检查奖励表面形式、惩罚静态值，与公开承诺矛盾；④五份分数全部为历史存档直接回放，不可复现 |
| 最小修复方案 | 任务文件（1 项）：Instruction 补三句话——门店状态判定口径、越界期 0 值的占位语义、三类门店影响的计算公式。评分器（4 项）：①实际结算严格使用公开的新 Rubric（公开权重=实际权重）；②闭合与贡献类维度以数值复算判定，取消对表头布局契约的依赖；③删除公式/关键词类形式检查，静态值与公式完全等价；④取消历史分直接回放，重新评分并输出维度级得分明细。另需确认 solve.py 的存在性与各 Agent 环境一致性 |
| 修复后需要重新检查的证据 | ①五份 rollout 重算分与当前分对照（预期收敛且可由数值正确性解释）；②三个 probe 送评结果符合合理评分基准（错者失分、缺者比例化、空者趋零）；③等价表达样本（T1）同分；④修复后评分脚本的维度级输出可公开复算 |

**判断依据（任务=需要返修）**：任务目标明确、材料充足、关键指标可独立复算、五份真实输出证明不同 Agent 都能完成——任务本身可用；但 Instruction 缺关键业务口径（状态判定、占位零语义、影响公式），且 solve.py 与环境一致性无法确认，属"少量返修即可"而非"通过"。

**判断依据（评分器=不可用）**：不是局部问题，而是系统性失效——分数由未公开规则产生、由布局而非数值决定、对真实 rollout 已造成 0.71 的同质量分差，且不可复现。当前分数不能可靠反映业务质量。

## 5.2 回归与对抗测试设计

说明：以下均为**测试设计 + 新 Rubric 下的预期评分行为**。新评分器尚未实现，现有 Scorer 快照缺少运行时组件（契约文件、语义缓存、判定时运行库）无法实际执行——**未执行任何测试，无伪造结果**。每个测试的通过标准均可客观判定。

| 测试编号 | 测试目标 | 输入变更 | 预期行为 | 防止的误判类型 |
|---|---|---|---|---|
| T1 等价表达 | 表达形式不影响得分 | 构造两份业务内容完全一致的受控样本：A=宽表+公式+常规命名；B=长表+纯静态值+不同表名与顺序。数据、计算、来源、结论逐项相同（与 rollout-04/05 的区别：那是"两条链正确"的推断等价，本测试是构造的全部内容严格等价） | A、B 得分相同（差值=0）；逐维度得分一致；不因公式/静态值、表名、顺序、表方向有任何分差。通过标准：\|分A−分B\|=0 | 假阴性、形式主义评分 |
| T2 符号错误 | 识别真实计算错误且保留正确部分 | 新变体（区别于 probe-01 的分母错误）：品牌总量与全部原值保持正确，仅将期间一午餐的关闭影响由 −24 改为 +24，并同步污染该餐段净变化与结论，其余 5 条餐段链与组合桥保持正确 | 识别该符号错误：期间一午餐链贡献部分失分、闭合断言失败；其余 5 条餐段链与组合桥、原值维度得分不受影响；同一错误传播到的 3 个位置（分量/净变化/结论）按一个根因扣分，扣分量不因传播位置数放大。通过标准：失分恰好集中于"期间一午餐链"+ 该根因登记一次 | 假阳性、漏检、重复扣分 |
| T3 表面合规缺证据 | 拒绝形式与自证 | 新变体（区别于 probe-03 的纯占位）：表结构完整，含两期间、全部门店名、总结段落，且每段结论都写"已核验"；但所有关键数值无来源定位、主要结论无数值支撑、勾稽仅为自证文字（附一张"核对清单"表但只有"通过"无两侧数值） | 标题/篇幅/关键词/"已核验"字样产生零正向分；无来源数值对应的维度记"不可验证"不给分；有数值但无来源的链不得追溯分；总分显著低于任何真实完成样本。通过标准：D7=0，D1–D6 中无证据部分=0，且无任何维度因自证措辞得分 | 假阳性、形式替代实质、自证替代证据 |
| T4 部分完成 | 比例化评价 | 新变体（区别于 probe-02 的"整期间缺失"）：两期间均交付；期间一全对；期间二品牌总量+组合桥正确，但餐段归因只写了早餐一行（午餐/晚餐缺失） | 期间一全部分得分；期间二总量与组合桥得分；期间二餐段维度仅按已完成的早餐链给分，缺失的午餐/晚餐链不得分；总分≈90 分档（非零、非满）。通过标准：期间一零失分、期间二餐段失分恰好=2 条链的权重、无任何整体清零 | 假阴性、部分完成被整体否定 |
| T5 根因传播去重 | 单根因不多扣 | 在 T2 变体上扩展：同一符号错误同时污染状态说明表、组合桥汇总行、餐段表、结论段落（4 处表现） | 四处失分登记为同一根因的四个受影响位置；扣分按"期间一午餐链"一次计入，不因四处表现重复扣；维度级输出中四处均标注"根因 R-1"。通过标准：该根因总扣分量 = 1 条链的贡献部分 + 闭合断言，可逐维度复算 | 重复扣分 |
| T6 解析失败区分 | 格式不支持≠业务错误 | 三份文件：①合理但冷门的格式变体（如多级表头+合并单元格的宽表）；②损坏文件；③真实数值但故意用评分器不支持的公式函数 | ①换解析路径重试后正常评分（不记候选人有错）；②按"不可读"处理并记录，不得推断业务错误；③数值仍可静态读取的部分正常给分，仅公式动态重算能力不给分。通过标准：三份均不产生"因解析问题扣业务分"的结果 | 假阴性、把评分器缺陷转嫁候选人 |

T1–T4 为必做测试，分别覆盖合法等价表达、实质业务错误、表面合规缺证据、部分完成四类风险；T5/T6 为增强项。所有测试的预期行为均可由新 Rubric 的公开条款直接推导，评分器实现后可逐条机器判定通过与否。

## 5.3 最终综合判断

1. **任务本身适合用于 Agent 能力评估**：材料真实完整、业务归因链条有区分度（五份真实输出水平可辨）、结果可客观验证；补齐 Instruction 三句话口径并确认环境一致性后即可使用。
2. **当前评分器不可直接使用**：见 5.1 判断依据。
3. **新 Rubric 解决了已发现的主要公平性问题**：公开权重=实际权重（可复算）；判定依据改为数值复算而非布局绑定；删除形式主义检查、静态值与公式等价；内置根因去重与部分完成规则；人工复核压缩到一个维度且锚定可判定点。
4. **四个测试验证的关键能力**：T1=表达形式中性；T2=抓得住错误且不误伤正确部分；T3=骗不过自证和外壳；T4=部分完成按比例给分。
5. **修复后重新认定可用所需证据**：5.1 表内四项（rollout 重算对照、probe 送评、T1 同分、维度级输出可复算），全部满足且公开脚本可独立复算后，方可认定评分器可用。
