# 4.5.1 五份 Rollout 假阴性分析

> 证据链：第三阶段五份独立审计（两条业务链数值全对）× frozen 历史评分记录（复算 5/5 吻合）×
> scorer_logic_audit.md（权重/绑定/R9 机制）。
> 纪律声明：第三阶段只覆盖餐段贡献 + 状态边界两条链，**不能据此断言五份工作簿整体质量完全相同**；
> 本报告对 rollout-01/02/04 的定性为"**审计范围内已确认的质量-分数不匹配**"，整体判定受范围限制。

## 1. 质量与分数对照总表

| Rollout | 两条链审计 | 当前分数 | 分数构成（复算） | 失分项（加权） |
|---|---|---:|---|---|
| rollout-01 | 全对 | 0.294424 | R4(23.45%)+R9(6.00%) | R5、R6B、R6E 记 0 |
| rollout-02 | 全对 | 0.294424 | 同上 | 同上（与 01 预存 completion 全同） |
| rollout-03 | 全对 | 0.944424 | +R6B(30%)+R6E(35%) | R5 记 0 |
| rollout-04 | 全对 | 0.350000 | R4+R5(5.56%)+R9 | R6B、R6E 记 0 |
| rollout-05 | 全对 | 1.000000 | 五项全 1 | 无 |

## 2. 逐份调查

### rollout-01（0.294424）

- 审计范围内业务质量：餐段链 6/6 正确（含分母 48/59、双闭合）、状态 12/12 正确、占位零规范。
- 分数解释：预存 completion 中 R5=0（餐段贡献表未绑定）、R6B=R6E=0（控制表未绑定）→ 仅剩 R4+R9。
- **R4=1 恰证明其组合桥数值被正确识别**；同一份工作簿的餐段表数值同样正确却未被识别（R5=0）→
  失分不是质量导致，是**绑定/布局**导致。
- 判定：**审计范围内已确认的假阴性**。证据边界：绑定失败的确切表头原因无法核验（contract.json 缺失）。

### rollout-02（0.294424，与 01 相同）

- 与 01 分数相同的原因已确认：frozen 预存 completion 在所有加权项上完全一致（R4=R9=1、R5=R6B=R6E=0；
  唯一差异 R6A 无权重）→ 复算同分。这不是巧合，是**记录级相同**。
- 业务质量独立核验：与 01 不同结构（长表），但两条链同样全对。
- 判定：**审计范围内已确认的假阴性**，机制与 01 相同（绑定失败 + 未公开权重结构）。

### rollout-03（0.944424）

- 得分来源：R6B=R6E=1 是高分主因（+65%）；R5=0 说明其餐段表也未绑定——但餐段数值本身正确（阶段三已验证）。
- 判定：高分与审计结果方向一致 → **不构成假阴性**；但其 5.56% 的 R5 损失同样源于绑定而非质量，
  属同一机制的低剂量表现。

### rollout-04（0.350000）

- 审计范围内业务质量：两条链全对（"餐段数值标在首行"为合理结构差异，数值无误）。
- 分数解释：R5=1（餐段表绑定成功）但 R6B=R6E=0（控制表未绑定）→ 65% 权重归零。
- 与 rollout-05 对比：05 与 04 数值同为全对，差在控制表是否绑定 → **0.65 的分差由布局决定**。
- 判定：**审计范围内已确认的假阴性**。

### rollout-05（1.000000）

- 五项加权维度全 1；两条链审计全对；其他维度（R1/R2/R3/R7 等）在预存记录中也全 1，
  但**这些维度不结算权重**（除 completion 记录外不影响分数）。
- 判定：审计范围内**合理**；满分是否有未审计维度的质量支撑无法确认（范围外不下结论）。

## 3. 非业务因素核对（形式主义评分）

| 因素 | 证据 | 与分数关系 |
|---|---|---|
| 公式 | 五份各含 536–1412 个公式；R9 五份全 1 | R9 对五份无区分度；若静态值则必失 5.99%（结构性歧视，见 FN-S） |
| 关键词 | R8 五份全 1（均有"来源/追溯"类词） | 当前权重 0，无影响；暴露关键词敏感性 |
| 表结构/绑定 | R5：01/02/03=0 而 04/05=1；R6B/R6E：仅 03/05=1 | **分数差的唯一解释变量**（在"数值全对"前提下） |
| 历史路径 | 五份全部 frozen 回放 | 分数与当前代码行为脱钩 |

## 4. 假阴性认定汇总

| 案例 | 认定 | 依据 |
|---|---|---|
| rollout-01 | 审计范围内已确认假阴性 | 数值全对（阶段三）+ 失分全部来自绑定/权重结构（复算） |
| rollout-02 | 同上 | 同上 + 与 01 记录级同分 |
| rollout-04 | 同上 | 同上；与 05 的 0.65 分差由控制表绑定解释 |
| rollout-03 | 不成立（方向一致） | 高分与质量相符 |
| rollout-05 | 不成立 | 满分与审计范围质量相符 |
| 静态值表达（结构性） | 机制已确认，样本待补 | R9 源码机制 + rubric 矛盾；尚未构造静态值实物样本（阶段五可补） |

## 5. 证据边界声明

1. "两条链全对" ≠ "工作簿全部维度质量相同"；本分析结论以审计范围为限。
2. 绑定失败的确切键/表头原因无法核验（contract.json 不在快照中）；本分析确认"失分由绑定差异造成"（结果侧 5/5 复算），原因侧为合理推断。
3. 五份分数均为 frozen 历史回放，不代表当前部署下的重算结果。
