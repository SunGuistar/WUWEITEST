# DEVELOPMENT PLAN

本项目采用 Stage Gate（阶段门禁）管理：每个阶段完成后汇报自检结果，等待人工批准，未获批准不得进入下一阶段。

**例外：阶段二采用"顺序执行、自动流转、失败中断"的节点质量门禁机制**——六个节点内部依次自动推进，节点验收不通过时立即停止整个阶段二并汇报；六个节点全部通过后才停止并等待人工验收批准进入阶段三（详见阶段二）。

## 阶段二：材料结构化与事实基线

执行机制：六个节点严格按序执行；每节点完成后立即对照本节点的验收标准逐项自检（含自动化测试与证据记录）；**通过则自动进入下一节点，不等待人工逐节点批准**；**不通过则立即停止整个阶段二的后续执行**，按失败汇报格式报告（未通过条件、问题证据、影响、最小修复建议），修复后重新验收当前节点；不得跳过失败节点、不得带着未解决的阻断问题继续。

### 节点 2.1 原始材料盘点与业务口径分析

- 实施：盘点考试包原始材料（instruction、materials 台账、gold、rollouts、probes、rubric、scorer），确认可读性与完整性；梳理台账字段、两个比较期间、门店状态定义（持续/新开/关闭）、餐段口径（早餐/午餐/晚餐）与数据异常。
- 产出：材料盘点记录与业务口径说明。
- 验收标准：所有原始材料可读且完整；字段、期间、状态、餐段口径全部确认；已识别的数据异常有记录；口径不确定项已列为待确认（不得擅自判定）。

### 节点 2.2 数据模型设计与标准化规则

- 实施：基于 2.1 确认的真实材料设计 Pydantic 模型（门店、期间、餐段、状态、客流量），定义字段映射、缺失值处理规则和来源追溯结构（文件→工作表→行列）。
- 产出：数据模型定义与标准化规则文档/代码骨架。
- 验收标准：模型字段与原始材料一一对应；缺失值与异常值处理规则明确；每条数据可追溯到来源位置。

### 节点 2.3 原始材料解析与 JSON 标准化

- 实施：实现台账解析与标准化转换，输出标准化 JSON，记录解析异常，编写解析测试。
- 产出：解析代码、标准化 JSON 快照、异常记录、解析测试。
- 验收标准：台账全部数据行被解析且标准化结果可复核；解析异常均有记录；解析测试通过。

### 节点 2.4 SQLite 存储与数据一致性

- 实施：实现 SQLite Schema、数据导入与查询，完成 JSON 与 SQLite 的一致性检查。
- 产出：SQLite 数据库、导入与查询代码、一致性检查结果。
- 验收标准：Schema 与数据模型一致；JSON 与 SQLite 中的数据完全一致（记录数、关键字段值逐项核对）；一致性检查通过。

### 节点 2.5 独立计算事实基线

- 实施：独立计算品牌总客流、净变化、门店组合桥（持续/新开/关闭）与餐段贡献，并与 Gold 对照记录差异。
- 产出：事实基线（JSON + SQLite）、与 Gold 的差异检查记录。
- 验收标准：两个比较期间的品牌总量与净变化可独立复算；抽查的组合桥与餐段贡献链的状态、绝对影响、分母、符号、闭合关系全部可追溯；与 Gold 的差异已逐项记录。

### 节点 2.6 数据质量校验与阶段验收

- 实施：数据质量检查、计算闭合验证（组合桥/餐段贡献与总量闭合）、来源追溯检查、自动化测试补齐、阶段总结报告。
- 产出：质量检查记录、完整测试套件、阶段二总结报告。
- 验收标准：闭合关系全部成立；来源追溯抽查通过；全部自动化测试通过；无影响后续阶段的未解决阻断问题。

预期产出（整个阶段）：`data/` 下的标准化 JSON 与 SQLite、事实基线、Gold 差异记录、阶段总结报告、可运行的测试。

阶段状态：技术实现与数据验证已完成，第一部分正式答卷已完成（`data/reports/part1_feasibility_and_fact_baseline.md`），等待人工验收
